# Per-Role Widget Class Access Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restrict which widget *types* (widget classes) a role can see in the "Add widget" catalog and on its resolved dashboard, with a safe opt-out default so existing dashboards are unaffected.

**Architecture:** New AD table `ETMETA_WIDGET_CLASS_ACCESS` (widget class → role), managed as a child tab of the existing Widget Class window. Access is enforced in three backend read/write points via one shared rule. **Rule (opt-out):** a widget class with *zero* access rows is visible to everyone; once it has *at least one* row it is restricted to the listed roles only. This mirrors the classic `OBKMO_WidgetClassAccess` semantics. **No frontend changes** — the workspace-ui dialog and layout renderer consume whatever the backend returns.

**Tech Stack:** Java (OpenBravo DAL + Hibernate HQL), Etendo Application Dictionary, dev-assistant webhooks (`/etendo:alter-db`, `/etendo:window`), JUnit.

**Ticket:** ETP-4631 · Branch: `hotfix/ETP-4631` · Module: `com.etendoerp.metadata`

## The shared access rule (implemented once, used three times)

HQL correlated-subquery fragment, parameterized by the widget-class path:

```
and (
  not exists (from etmeta_Widget_Class_Access a where a.widgetClass = <CLASS_PATH> and a.active = true)
  or  exists (from etmeta_Widget_Class_Access a where a.widgetClass = <CLASS_PATH> and a.active = true and a.role.id = :roleId)
)
```

- Catalog query: `<CLASS_PATH>` = `wc`
- Layout query: `<CLASS_PATH>` = `dw.widgetClass`
- POST guard: equivalent boolean helper (see Task 5)

Enforcement points:
1. `WidgetClassesService.CLASS_HQL` — catalog ("Add widget")
2. `DashboardLayoutResolver.HQL` — dashboard layout
3. `DashboardService.handlePostWidget()` — server-side guard (defense in depth: a restricted `classId` must not be addable via a crafted POST even though the catalog hides it)

- [ ] **Step 3: Create the shared helper**

```java
package com.etendoerp.metadata.widgets;

import org.openbravo.dal.service.OBDal;
import org.hibernate.query.Query;

/** Opt-out role access for widget classes: no access rows → allowed for all;
 *  any access rows → allowed only for the listed roles. */
public final class WidgetClassAccessRule {
    private WidgetClassAccessRule() {}

    public static boolean isAllowed(String widgetClassId, String roleId) {
        Query<Long> restricted = OBDal.getInstance().getSession().createQuery(
            "select count(a) from etmeta_Widget_Class_Access a " +
            "where a.widgetClass.id = :cid and a.active = true", Long.class)
            .setParameter("cid", widgetClassId);
        if (restricted.uniqueResult() == 0L) return true; // safe default
        Query<Long> granted = OBDal.getInstance().getSession().createQuery(
            "select count(a) from etmeta_Widget_Class_Access a " +
            "where a.widgetClass.id = :cid and a.role.id = :rid and a.active = true", Long.class)
            .setParameter("cid", widgetClassId).setParameter("rid", roleId);
        return granted.uniqueResult() > 0L;
    }
}
```
